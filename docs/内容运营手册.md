# TVCN 内容运营手册

> 最后更新：2026-11-27。适用 8 个内容站 506 对中英内容（1,012 篇 Markdown）。命令与门槛以 `node generator\build-all.mjs` 的实际输出为准。

## 1. 这份手册管什么

不再新增同质页面。所有内容工作只做四件事：让来源可核、让深度达标、让内链成网、让页面可长期维护。任何「再写 100 篇」的提议先回到这四条，不通过就不立项。

唯一内容源是 `content/` 里的 Markdown；`generator/data/static-articles-data.json` 只是页面壳缓存。改正文只改 Markdown，构建会自动重建索引并同步正文。

## 2. 来源分级

| 等级 | 来源类型 | 例子 | 用法 |
|---|---|---|---|
| A | 官方规范、监管文本、标准组织、厂商规格书 | SMPTE、ITU、DCI、W3C、法规原文、ARRI/Sony/Canon 官方文档 | 参数、标准、法律、器材规格必须优先 |
| B | 行业机构、博物馆/档案馆、同行评审论文 | BFI、ASC、ACM/SIGGRAPH、arXiv | 历史、方法、研究结论 |
| C | 有编辑把关的行业媒体/专业书 | 有作者、日期、编辑流程的 trade publication | 只作补充，不能单独支撑硬参数 |
| 禁用 | SEO 内容农场、无署名清单、联盟营销页、搬运站 | — | 不作为来源 |

引用只认「可点开的链接 + 写明用途 + 访问日期」：

```markdown
- [S23] [SMPTE 标准入口](https://www.smpte.org/standards) — 2026-11-26 访问。用于核对时间码与信号链术语；不替代现场测试。
```

规则：

1. 一条来源只用于它真正支撑的段落，不写「综合参考」「详见官网」。
2. 每条来源写清「核对哪一段」和「不替代什么」；参数页写「不替代实测」，法律页写「不构成法律意见」。
3. 同一页最多 5 条来源。
4. 来源块统一 `<!-- SOURCES_START -->` → `## 参考与延伸阅读` → `<!-- SOURCES_END -->`。
5. `content/SOURCES.md` 是注册表；页面里不允许出现「见 SOURCES.md」的占位。
6. 外链健康分 `ok / manual / broken`。脚本被反爬拦住的官方页登记在 `KNOWN_BLOCKED`；`broken` 必须换源或删除。

## 3. 经验页

没有外部公开来源、但来自现场/项目复盘的页面用 `source_kind: experience`，文末给可核条件：

```markdown
## 经验说明

经验说明：本页来自 N 次现场复盘，条件为单机位、自然光或一盏主光；页面讨论的具体对象是「标题」；不含外部实验室测试，条件变化时结论可能失效。
```

必须写清：次数或项目数、拍摄/后期条件、适用对象、不包含什么。案例页统一写「匿名复合复盘，来自多个同类型项目的合并与改写；金额与周期为区间，人物、地点与客户信息已隐去，不对应单一真实客户」。

能找到 A/B 级公开来源的深读、方法、法规、器材页必须转 `sourced`；纯经验只留给无法公开验证的现场判断。

## 4. 页面类型与篇幅

| 类型 | 目标 | 结构 |
|---|---|---|
| 深读 `deep-*` | 中文 1500 字以上 | 问题、条件、步骤、失败、验收、延伸；至少 6 个 H2 |
| Field note | 中文 600–1000 字 | 现场条件、动作、判断信号、边界 |
| 案例 `case-*` | 中文 1200 字以上 | 任务、限制、排期、预算、决定、翻车、结果、可复用清单；必须有案例说明与结构图 |
| 卡片 `tool-card-*` | 中文 300–500 字 | 一句判断、三个检查、一个替代方案 |
| 工具/计算器 | 中文 450 字以上 | 选型、边界、现场、怎么做、别踩、验收；计算器另有公式、输入、输出、边界 |
| 模板/片型 | 中文 600 字以上 | 结构、逐段动作、常见失败、验收 |

硬门：

- 可见正文中文不得少于 300 字；300–449 字必须加深，不能靠来源块凑字数。
- 每页至少 3 个 H2；深读至少 6 个；同一页不出现重复 `##` 标题。
- 每页 3 条 related，分属不同子主题。
- 每页至少 2 条站内入站，不允许孤立页。

## 5. AI 披露、案例匿名化、价格与法规

- AI 生成图必须标注「AI 生成/示意」，不得放在「现场截图」「实测样片」位置。
- 不伪造案例、测试、客户、奖项、播放量。案例只能是匿名复合复盘，金额写区间。
- 价格页写「采集日期、币种、含税/不含税、地区」；超过 90 天标「价格待复核」。
- 器材页写清「实测/公开规格/未实测」；没实测的参数不做数值结论。
- 法规与平台规则页写「适用地区、生效日期、不是法律意见」；每 6 个月复核。
- 明确不做：Search Console、访问统计、Newsletter、视频/联盟/商业化、AI 样片、301。

## 7. 角色

- 内容编辑：选题、正文、来源、经验说明、related。
- 技术复核：参数、法规、器材规格、外链健康。
- 发布：构建、canary、全量、Pages 与线上核验。

任何角色改完都跑同一套检查；不另建「最终版清单」，以 Git 历史与审计 JSON 为准。
