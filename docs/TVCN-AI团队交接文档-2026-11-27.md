## 6. 标准工作流

### 6.1 只读体检

```powershell

```

预期：


再检查：

```powershell
& 'C:\Program Files\Git\cmd\git.exe' -C content status --short
& 'C:\Program Files\Git\cmd\git.exe' -C deploy\main status --porcelain
```

### 6.2 修改一篇现有文章

```powershell
# 1. 改 content/<site>/zh|en/<slug>.md
# 2. 重建索引
python generator\make-content-index.py

# 3. 同步 Markdown 正文到静态数据
python generator\sync-static-bodies.py
# 预期：synced 1012 pages; ... missing 0

# 4. 全量构建与 QA
node generator\build-all.mjs
```

注意：

- `sync-static-bodies.py` 会保留图解 figure；当前已验证 989 个带 `figure class="diagram"` 的页面不丢。
- 只改 Markdown 不跑同步，`out/` 不会变。
- 只改 `static-articles-data.json` 不跑构建，`out/` 也不会变。

### 6.3 新增一对内容

当前仍是双源，新增一对需要同时处理 Markdown 和静态数据。步骤：

1. 在 `content/<site>/zh/<slug>.md` 与 `en/<slug>.md` 写正文和 frontmatter。
2. 准备图解：
   - `content/images/diagrams/zh/<slug>.svg`、`en/<slug>.svg`；
   - 站点实际引用 `assets/notes/<slug>.svg`、`<slug>-en.svg`，需要放到 `assets/notes/`。
3. 在 `generator/data/static-articles-data.json` 的 `zh`/`en` 数组各加一条：
   - 字段：`id`（slug）、`site`、`title`、`kicker`、`summary`、`meta`、`image`、`html`。
   - 最稳妥的做法是复制一个结构相近的现有条目，再替换字段和 HTML 结构；`html` 必须包含 `<article class="article-body">`。
4. 跑 `python generator/make-content-index.py`，确认 documents / pairs 增加。
5. 跑 `python generator/sync-static-bodies.py`，确认 `missing 0`。
6. 跑 `node generator/build-all.mjs`。
7. 检查新页 canonical、sitemap、related、入站链接、资源。

这是当前最不干净的一步。阶段六会改为直接从 Markdown 渲染，移除第 3 步。

### 6.4 改站点配置或 UI

- 站点配置：`site-kit/sites.json`（域名、repo、content_site、app、shared_pages）。
- 文章样式唯一真源：`site-kit/assets/article.css`。
- 页面壳：`generator/build-site.mjs` 里的 `page()/header()/footer()`。
- 交互壳：`app/tvcn-ui-v2.html`，只主站发布。
- 404 / robots / manifest / sw：`site-kit/shell/`。
- 改完跑 `node generator/build-all.mjs`。

### 6.5 改 AI 站

```powershell
# 1. 改 generator/ai6/content/*.py、schema.py、templates、evidence、samples
# 2. 构建
python generator\ai6\build_site.py --out generator\ai6\site
# 3. QA
python generator\ai6\qa_site.py --site generator\ai6\site
# 4. 全量构建会复制到 out/ai
node generator\build-all.mjs
```

AI 站不经过 `content/`，也不进内容站 sitemap。

### 6.6 全量重建

```powershell
node generator\build-all.mjs
```

### 6.7 发布

```powershell
# 只镜像到 deploy 并本地提交，不推送
powershell -ExecutionPolicy Bypass -File generator\publish.ps1 -Site story

# 推送
powershell -ExecutionPolicy Bypass -File generator\publish.ps1 -Site story -Push

# 全站
powershell -ExecutionPolicy Bypass -File generator\publish.ps1 -Site all -Push
```

规则：

- 先发一个分站做 canary，建议 story。
- 发布前必须 `build-all` 通过。
- `publish.ps1` 会保留 `deploy/<site>/.git`，用 `out/<site>` 覆盖工作区。
- 默认只提交，不推送；`-Push` 才推。
- 不要直接改 `deploy/` 或 `out/`。
