# TVCN 网站内容补全计划（2026-11-26）

**一句话目标：在不重复、不注水的前提下，新增 16 对真正有决策价值的文章，并把 16 对现有文章加深到可独立解决问题的程度。**

这份计划接在 `网站内容改善报告-2026-11-26.md` 之后。上一轮把 490 对现有内容做到了 A/S；这一轮不再只做“修补”，而是补内容缺口和文章深度。

---

## 1. 现状与为什么要补

| 指标 | 当前 |
|---|---:|
| 中英内容对 | 490 对 / 980 页 |
| 质量分布 | 468 A + 22 S，0 B、0 硬缺陷 |
| 深读对 | 117 对 |
| 非深读 article / history / literacy | 261 对 |
| 300–499 字页面 | 33 对 |
| AI 站 | 49 个索引页，45 A + 4 S |

现有内容的短板不是“没有页面”，而是三类：

1. **有入口、缺完整决策**：story、shoot、post 都有单个技巧页，但缺少把多个条件放在一起做判断的深读。
2. **有模板、缺条件差异**：formats 的“拉片 / 结构 / 模板”很全，但部分片型只有模板，没有“什么时候不该用”。
3. **有历史/素养条目、缺解释链**：context 46 对里只有 5 对深读，历史页多为年表式短条目。

所以这次新增和加深都围绕“补决策链”，不做同义扩张。

## 3. 页面标准（继承上一轮，但加深要求更高）

### 3.1 新增深读必须有的结构

1. **现场**：谁、在什么限制下、要交什么。
2. **判断**：3 个可观察信号，读者能当场用。
3. **动作**：5 步以内，每步带条件/数字。
4. **失败**：3 个具体失败模式，不是“注意细节”。
5. **边界**：什么情况下不要用这套方法。
6. **练习**：10 分钟可做的复现任务。
7. **验收**：3 条可检查结果。
8. **深读块**：两种条件不同的做法、一个反例、一个可复用模型。
9. **来源**：2 条，分别绑定具体 H2；不把来源当装饰。
10. **图解**：一张能看懂流程/对比的结构图，中英各一张。

### 3.2 加深现有文章必须有的增量

- 不是把原文重复一遍，而是新增：
  - 一个条件不同的做法
  - 一个真实失败模式
  - 一张对照表或决策表
  - 一段“如果现场只能做一件事，先做什么”
  - 3 条新增验收
- 保留原有标题与 slug；只加 `depth: deep`、`deep_minutes` 和 `<!-- DEEP_DIVE_START -->` 深读块。
- 原文中的具体数字、来源和边界不能因为加深被删掉。

### 3.3 全站底线

- 每对中英同构：同一组数字、同一组失败、同一组来源。
- 3 条 related 分属不同子主题；新增页至少 2 条同站、1 条跨站。
- 新页面必须满足 0 空 H2、0 通用模板句、0 硬缺陷。
- 图解 alt/caption 写“看哪两处、判断什么”，不写“示意图”。
- 任何经验型页面保留 `source_kind: experience`，不伪装 sourced。

## 4. 执行顺序

1. **P0 计划审核**：检查 slug 唯一、标题不重复、每站 2 对、16 个对象都有来源/图解/related；不过审不写正文。
2. **P1 新增内容**：按站分批生成中英 Markdown 与 SVG；每批先跑内容质量审计，再进下一批。
3. **P2 深度升级**：按站给 16 对现有页面追加深读块、设置 depth；保留原文与来源。
4. **P3 索引/静态层**：重跑 `make-content-index.py`、`extract-static-articles.mjs`、`make-static-articles.mjs`、`make-release.py`。
5. **P4 全量验收**：内容评分、来源主张、图解资产、内链、UI、静态 QA、9 站发布与 Pages 构建。
6. **P5 报告**：写 `网站内容补全报告-2026-11-26.md`，列新增/加深清单、A/S、失败项、残余风险。

没有日期门，不按“几月几日必须完成”推进；完成由页面审计和线上核验决定。
